# התקנה, תפעול ופריסה

## כניסה ואבטחה
תלמידים מזינים קוד בית ספר ובוחרים כיתה ושם. למנהל סיסמה נפרדת. SCHOOL_CODE ו־ADMIN_PASSWORD מוגדרים כסודות בשירות האירוח בלבד. סיסמת מנהל: 12 תווים לפחות; קוד בית ספר: 4 לפחות. שינוי סודות מחייב פריסה חדשה.

בחירת שם אינה אימות זהות אישי: כל מחזיק בקוד יכול לבחור שם. יש להפיץ את קוד בית הספר רק בקהילה. מדיניות הגישה של Sites חלה בנוסף לכניסה במשחק; האתר הנוכחי ציבורי, והמחסום לתלמידים הוא קוד בית הספר בלבד. אין צורך ב־GitHub לתלמידים.

הכניסות נשמרות בשרת כ־hash עם תפוגה, cookies מסוג HttpOnly, Secure, SameSite והגנת CSRF. פתרון השאלה אינו נשלח לפני מענה; אחרי טעות נשלחים התשובה שנבחרה והפתרון לצורך למידה. בניהול ובקובצי גיבוי יש מידע אישי ולכן שומרים גיבויים במקום פרטי.

## התקנה וחיבור בסיס הנתונים
Node 22.12+: npm ci, npm run build, npm test.
האתר משתמש ב־Cloudflare Worker עם binding בשם DB ל־D1 ו־ASSETS לקבצים. Sites מקצה את בסיס הנתונים לפי d1 במניפסט .openai/hosting.json. אין להכניס אליו סודות.

db/schema.ts מגדיר טבלאות. drizzle/0000_*.sql הוא סכמה שנוצרה עם Drizzle, ו־0001_atomic_game_rules.sql מגדיר טריגרים אטומיים. לאחר שינוי סכמה: npm run db:generate. אין לשנות מיגרציה שכבר הוחלה; מוסיפים חדשה.

טבלאות: tractates/chapters/mishnayot לשלד; content לטקסטים, שאלות, מקור, סטטוס וגרסה; rounds/completions להיסטוריה; tickets ליומן תנועות; leases לניסיון האישי הנוכחי; cooldowns נשמרת כתשתית היסטורית ואינה נאכפת; classes/students; sessions/login_limits; settings/audit.

בבסיס חדש נזרעים כל 149 המזהים, התוכן המלא וארבעה תלמידים פיקטיביים בשתי כיתות. זו פעולה חד־פעמית; פריסה נוספת אינה דורסת תוכן או התקדמות.

## ייבוא משניות ושאלות
בניהול: בחירת ״תוכן משניות ושאלות״, העלאת Excel המקורי או JSON, ״בדיקת קובץ״ ואז ״שמירת הייבוא״. מסמנים בדיקת מאגר מלא אם כל 149 המשניות צריכות להיכלל.

Excel: הגיליון הראשון, 21 עמודות המאגר שסופק באותו סדר: מספר רץ; מסכת; פרק; משנה; טקסט; שאלה 1; ארבע אפשרויות; תשובה נכונה; רמז; שאלה 2; ארבע אפשרויות; תשובה נכונה; רמז; מקור; סטטוס.
נבדק/מוכן הופכים ל־ready; חסר ל־missing; היתר ל־review. רק ready משתתף בלימוד. כל המזהים מופיעים במפה תמיד.

JSON הוא מערך רשומות:
```json
{"id":"sukkah:1:1","text":"טקסט מנוקד","status":"ready","source":"כתובת מקור","questions":[{"prompt":"שאלה 1","options":["א","ב","ג","ד"],"correct":"א","hint":"רמז"},{"prompt":"שאלה 2","options":["א","ב","ג","ד"],"correct":"ב","hint":"רמז"}]}
```
התשובה הנכונה היא טקסט מתוך האפשרויות, ולא מיקום. השרת מערבב אפשרויות ומחליף מזהים בכל ניסיון חדש.

הבדיקה מדווחת על משנה חסרה או כפולה, מזהה לא תקין, שאלה חסרה, פחות מארבע תשובות, תשובות כפולות ותשובה נכונה שלא קיימת. שגיאה מונעת את כל הייבוא. השרת בודק שוב בעת השמירה. ייבוא מעדכן רק תוכן ולא השלמות/כרטיסים. לימוד פעיל שומר צילום תוכן וגרסה עד סיומו. לעדכון משנה אחת אפשר לייבא רשומת JSON יחידה. דרך הניהול ניתן לייצא את המאגר המעודכן.

המרה מקומית: python scripts/convert_workbook.py source.xlsx data/content.json.
עדכון הקובץ במאגר הקוד אינו מעדכן בסיס חי; יש לייבא אליו דרך הניהול.

## ייבוא תלמידים
CSV UTF-8, Excel או JSON עם id,name,class_id,class_name. דוגמה: data/students-example.csv.
ב־Excel נתמכות גם ״מזהה תלמיד״, ״שם תלמיד״, ״מזהה כיתה״, ״כיתה״.
מזהים נשארים קבועים. עדכון שם או כיתה שומר כרטיסים והיסטוריה. תלמידים שאינם בקובץ אינם נמחקים; חשבונות מושבתים אינם מופעלים מחדש. לאחר העלאת רשימה אמיתית משביתים את חשבונות ההדגמה בניהול. שינוי פרטי תלמיד אפשרי בייבוא רשומה אחת. אין לשמור רשימות אמיתיות ב־GitHub.

## כללי משחק ותיקונים
ברירת מחדל: ניסיון לימוד 900 שניות, ניתנת לשינוי בניהול. אין השהיה לאחר טעות.
אחרי טעות השרת שומר את הניסיון ואת תוקף הניסיון, ומחזיר את התשובה שנבחרה (אדום) והנכונה (ירוק מודגש). כפתור חזרה למשנה מפעיל reread; לאחר הקריאה נבחרת השאלה האחרת ומעורבבות האפשרויות מחדש. טעויות נוספות מחליפות שוב בין שתי השאלות. חזרה לקריאה לפני מענה אינה מחליפה שאלה. מזהי תשובות ישנים אינם מתקבלים בניסיון חדש. כפילויות ובקשות מקבילות אינן משנות ניסיון שכבר נשמר. ניסיונות שפגו מסתיימים ללא תלות בדפדפן.
מיגרציה 0002 מבטלת את טריגר ההשהיה הישן; אינה מוחקת השלמות, כרטיסים או היסטוריית סבבים.

השלמה, כרטיס וסיום סבב נשמרים אטומית. כל תלמיד יכול ללמוד כל משנה מוכנה, גם במקביל לאחרים וגם כשהיא מסומנת כנלמדה. אינדקס ייחודי מונע שתי השלמות אישיות פעילות עבור תלמיד + משנה + סבב. ההתקדמות הבית־ספרית סופרת משניות ייחודיות.

עד 3 כרטיסי לימוד חדשים לתלמיד בכל יום לפי Asia/Jerusalem, בחצות המקומית ובהתאמה לשעון קיץ. המגבלה חלה בכל הסבבים יחד ונאכפת בטריגר בבסיס הנתונים. לכל משנה ניתן כרטיס אחד לתלמיד בסבב; אפשר לחזור ללמוד ללא הגבלה. אם לא הוענק כרטיס עקב המכסה, ניתן ללמוד אותה מחדש ביום אחר ולקבל את הכרטיס הראשון עבורה. כרטיסים היסטוריים נשמרים, גם מעבר למכסה. תיקונים ידניים אינם כרטיסי לימוד ואינם נכללים במכסה. ביטול כרטיס אינו מחזיר מכסה לאותו יום.

ביטול השלמה מפחית כרטיס רק אם הוענק, פעם אחת, ומשאיר היסטוריה. המשנה מפסיקה להיספר בבית הספר רק כשלא נותרה השלמה פעילה אחרת שלה באותו סבב. אין יתרות שליליות. תיקון כרטיס מחייב סיבה ונרשם ביומן.

בסיום כל 149 המשניות הייחודיות נפתח הסבב הבא אוטומטית ללא הגבלת מספר הסבבים. הבית והמפה מציגים את הסבב הנוכחי ומספר הסיומים. ניסיון שהתחיל בסבב קודם יכול להסתיים בו, בלי לקדם את הסבב החדש. הסבבים אינם נמחקים. ביטול בסבב סגור אינו פותח אותו או מוחק סבב חדש. התרומה הכיתתית סופרת לימודים אישיים לפי הכיתה בזמן ההשלמה ולכן יכולה לעלות על 149; הכרטיסים והתרומות מצטברים בכל הסבבים.

## ייצוא, גיבוי ושחזור
ייצוא CSV: תלמידים, יתרות כרטיסים, השלמות והיסטוריה, תרומות כיתות ורשימת הגרלה עם שורה אחת לכל כרטיס. מחרוזות מוגנות מהפעלת נוסחאות ב־Excel.

״הורדת גיבוי מלא״ יוצרת צילום עקבי של תוכן, תלמידים, סבבים, השלמות, כרטיסים, הגדרות ויומן. אינו כולל סיסמאות/כניסות זמניות. שמרו במקום פרטי נוסף לפני שינויים מהותיים ובסוף כל יום פעילות. אין כרגע גיבוי חיצוני מתוזמן אוטומטית.

לשחזור: הורידו תחילה גיבוי נוכחי, פתחו ״שחזור מגיבוי״, העלו JSON ואשרו החלפת נתונים. פעולה אטומית: שגיאה מבטלת הכול. כל הכניסות מתבטלות. היכנסו מחדש ובדקו סבב, מספר השלמות ויתרות. עד 4MB ו־10,000 רשומות בממשק; מעבר לכך השתמשו בגיבוי D1 אצל ספק האירוח. CSV אינו תחליף לגיבוי מלא.

## פריסה ב־Sites
npm run build יוצר dist/server/index.js, dist/client ו־dist/.openai עם המניפסט והמיגרציות. שומרים את המקור, אורזים ומפרסמים דרך Sites. הגדרות סודיות מועברות דרך Sites בלבד. המיגרציות מוחלות לפני העלאת השרת.

## העברה לשרת Cloudflare עצמאי
צרו D1 בחשבון היעד, הגדירו DB, assets מ־dist/client עם binding בשם ASSETS, ו־main ל־dist/server/index.js. הגדירו את שני הסודות. הפעילו את המיגרציות לפי הסדר והעלו את ה־Worker. לאחר אתחול, שחזרו את JSON הגיבוי דרך הניהול. בחנו עלויות ומגבלות בחשבון היעד לפני הפעלה.

## אב־טיפוס Flask
הקבצים server.py, migrations/001.sql, Dockerfile ו־render.yaml נשמרו לעיון היסטורי בלבד. הם אינם מתוחזקים מול הממשק וכללי המשחק הנוכחיים. אין לפרוס אותם עם הממשק הנוכחי; לפריסה עצמאית השתמשו בהוראות Cloudflare שלעיל.

## צוות בית הספר
בוחרים „כניסת צוות”, מזינים את STAFF_CODE הסודי ובוחרים שם. קוד התלמידים SCHOOL_CODE אינו חושף את רשימת הצוות ואינו מאפשר בחירת איש צוות, גם בבקשת API ישירה. צוות אינו מקבל הרשאות ניהול. כניסות ישנות של צוות שסומנו כתלמיד דורשות כניסה מחודשת. הלימוד פתוח גם לתלמידים במקביל: תשובה נכונה תורמת להתקדמות הסבב אם המשנה טרם נלמדה, אך אינה יוצרת כרטיס הגרלה. צוות אינו מופיע בלוח הכרטיסים או בקובץ ההגרלה. גם הוספה ידנית של כרטיס לצוות חסומה בשרת ובבסיס הנתונים. ביטול השלמת צוות אינו מפחית כרטיס.
בניהול ניתן לייבא צוות באמצעות JSON/CSV עם id,name בלבד, או Excel עם עמודות שם פרטי ושם משפחה. שדות אחרים אינם נשמרים. מזהים קבועים שומרים על היסטוריה; ייבוא אינו מחליף סוג משתתף קיים. is_staff נשמר בגיבוי; גיבויים ישנים ללא השדה משוחזרים כתלמידים. יש לבדוק ולהסיר מהאלפון רשומות ספקים ותוכניות לפני ייבוא, ולהשלים שמות חסרים בלי להמציא אותם.
